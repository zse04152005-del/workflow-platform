# 统一 Definition of Done

> 基线版本：1.0.0  
> 生效日期：2026-07-30  
> 机器策略：`config/governance/policy.json`  
> 适用范围：源码、契约、数据库、前端、部署、配置、测试和文档任务

## 1. 完成的含义

任务只有在本页适用项全部满足、验收命令有可复现结果、总控清单和需求追踪矩阵同步更新后，才能标为 `[x]`。“代码已写”“本机能运行”“人工看起来正常”都不是完成证据。

某项确实不适用时可以写 `N/A`，但必须记录理由；不能用 `N/A` 跳过安全、不变量、兼容性或迁移风险。一个任务跨多个领域时，取所有领域要求的并集。

## 2. 十二项完成检查

### DOD-01 范围与追踪

- 变更关联唯一的总控任务、缺陷 ID 或经批准的需求变更。
- 对应 Requirement ID 已确认；API、事件、表、测试和文档映射同步更新。
- 新发现需求先划分 MVP、二期或明确不做，禁止偷偷扩大当前任务范围。

### DOD-02 实现与架构

- 实现满足验收标准，没有遗留占位逻辑、静默失败、临时调试路径或未登记 TODO。
- 模块所有权和依赖方向符合 ADR；不能跨模块直连 Repository 或把 Redis/Kafka 当权威状态。
- 影响一致性、安全、公开契约、数据模型或部署拓扑时，ADR 已先更新并说明备选方案。

### DOD-03 API、Schema 与数据

- OpenAPI、DSL Schema、Event Schema、错误码和示例与实现一致。
- 兼容性分类已记录；破坏性变更具备新 Major、迁移窗口、回退方案和 ADR。
- 表、索引、外键、唯一约束、RLS、审计字段和数据保留规则已评审；数据库迁移只追加、不改写。

### DOD-04 自动化测试

- 正常、边界、失败和权限路径均有自动化测试；缺陷修复包含能复现原问题的回归测试。
- 状态机、事务、Kafka、租约、RLS、对象存储等关键能力使用真实基础设施验证，不能只靠 Mock。
- 新校验规则必须同时有正向样例和至少一个会被阻断的反向控制。

### DOD-05 安全、隐私与租户隔离

- 鉴权、对象级授权、tenant context、RLS、密钥引用和审计已覆盖正反向测试。
- 日志、错误、Trace、事件、审计、测试夹具和截图不含明文密钥、个人信息或敏感 Payload。
- 依赖、Secret、输入大小、注入、SSRF 和供应链风险按变更范围完成扫描或测试。

### DOD-06 可靠性、并发与恢复

- 事务边界、幂等键、去重、重试、租约、fencing、迟到结果和终态不变量均有明确语义。
- 并发竞争、重复消息、服务重启和依赖短故障不会造成重复推进或幽灵状态。
- 失败恢复、重放或补偿不会改写历史证据；不可撤销外部副作用已明确限制。

### DOD-07 可观测性与运维

- 关键路径具备结构化日志、低基数指标、Trace/Correlation ID，且字段已脱敏。
- 新故障模式有告警或可查询信号；值班人员能从信号定位到实例、节点、attempt 和证据。
- 新运维动作、依赖降级或恢复路径已更新 Dashboard、告警或 Runbook。

### DOD-08 性能与容量声明

- 只有存在固定环境、数据、Payload、并发、下游延迟、脚本、持续时间和 P50/P95/P99 时才能声明性能结果。
- 性能优化必须同口径前后复测；不以单次峰值或本地偶然结果作为结论。
- 没有性能影响时标记 `N/A` 并说明判断依据，不虚构数字。

### DOD-09 文档与示例

- README、API/Schema、ADR、Runbook、配置说明和调用示例与真实行为一致。
- 新配置项记录来源、默认值、是否敏感、环境覆盖和失败行为。
- 用户可见变化、限制、手工步骤和兼容性影响已清晰说明。

### DOD-10 迁移、部署与发布

- 数据库采用 expand-migrate-contract；空库、前一版本升级和重复执行路径已验证。
- 配置、镜像、资源限制、探针、优雅停机、兼容窗口和失败停止条件已覆盖。
- 发布物可追溯到不可变 Git SHA/Tag；需要回退或前滚时已有经过验证的步骤。

### DOD-11 证据与可复现性

- 证据记录包含日期、精确命令、环境、结果、关键文件和遗留风险。
- 只声明实际执行的本地/Hosted/生产级验证，不能把本地等价验收写成远程 CI 绿灯。
- 截图只能作为补充，不能替代自动化日志、测试报告或协议级验证。

### DOD-12 清理、评审与状态

- 无真实密钥、临时 `.env`、构建产物、调试日志、死代码、无原因抑制或无期限豁免进入提交候选。
- 工作镜像与桌面权威目录已同步并做哈希抽查/全量复核；用户已有无关改动未被覆盖。
- 总控清单填写 `[x]`、完成日期、证据和下一步；遗留项有唯一 ID，不以口头备注代替。

## 3. 变更类型的最低门禁

| 变更类型 | 必跑命令 | 额外要求 |
|---|---|---|
| 规划/治理/文档 | `pnpm governance:verify`、`pnpm governance:test`、`pnpm traceability:verify`、`pnpm secrets:verify` | 链接、状态和机器源一致 |
| Java/后端 | `./mvnw -B -ntp clean verify` | 相关集成/并发/架构测试 |
| Web Console | `pnpm verify` | lint、类型、组件测试、生产构建；关键页再跑 Playwright |
| 配置/Secret | `pnpm config:verify`、`pnpm secrets:verify` | 正反向配置/泄漏控制 |
| Flyway | `pnpm migrations:verify`、`pnpm migrations:test` | 空库和前一版本升级测试 |
| Compose | `pnpm compose:verify` | 需要运行时行为时再做协议级 smoke |
| CI | `pnpm ci:verify` | actionlint、最小权限、SHA/digest 固定 |
| 发布候选 | 全部适用门禁 + G11 最终验收 | 版本、迁移、SBOM、签名、恢复、演示与发布说明 |

`pnpm verify` 是 Web 与仓库策略聚合门禁，当前包含架构模型、领域数据约定、ER 模型、需求追踪、治理、配置、Secret、lint、类型检查、测试和构建；Java、迁移、Compose、CI 契约仍按上表显式执行。

## 4. 完成证据模板

```markdown
### 完成记录：Gx-xx 任务名

- Requirement：REQ-...
- 状态：[x]
- 完成日期：YYYY-MM-DD
- 实现与关键文件：
- 适用 DOD：DOD-01～DOD-12；N/A 项及理由：
- 验收环境、命令与结果：
- 正向与反向控制：
- Secret/敏感数据检查：
- 工作镜像/桌面同步复核：
- 遗留风险：无 / 唯一 ID + 处理阶段
- 下一步：Gx-xx
```
